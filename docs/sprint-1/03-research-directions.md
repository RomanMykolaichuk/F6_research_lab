# Розділ 3. Дослідницькі напрями кафедри інформаційно-аналітичних технологій

> Пропозиція для методичного посібника. Наведені напрями не слід називати офіційним переліком НУОУ без окремого рішення кафедри й відповідного документа.

## 3.1. Принцип побудови карти напрямів
Карту доцільно формувати за класом ІСТ, науковою задачею та типом результату, а не за назвами програмних продуктів. Напрям має допускати зміну інструментарію без втрати дослідницького ядра. Наприклад, «оцінювання ефективності інтеграції інтелектуальних компонентів» — стійкий напрям, а «дослідження конкретної LLM версії X» — лише можливий експериментальний контекст.

## 3.2. Матриця напрямів та результатів
| Напрям | Приклади наукових задач | Можливий результат | Типові метрики |
|---|---|---|---|
| Інформаційно-аналітичні системи | Інтеграція потоків, якість аналітичного циклу | Модель, метод, технологія | затримка, повнота, точність |
| СППР | Ранжування альтернатив за невизначеності | Метод багатокритеріальної оцінки | узгодженість, стійкість рангу |
| Інтеграція даних | Семантичне узгодження схем | Модель онтологій, метод інтеграції | втрати даних, узгодженість |
| Ресурсне управління | Адаптивне виділення обчислень | Модель середовища, метод керування | час, вартість, пропускна здатність |
| ШІ у складі ІСТ | Добір сервісів, контроль якості, пояснюваність | Метод оркестрації/оцінювання | якість, витрати, ризик |
| Графи знань | Розвиток представлення знань і персоналізації | Модель графа, інформаційна технологія | покриття, засвоєння, стабільність |
| Розподілені ІСТ | Інтероперабельність компонентів | Архітектурна модель, метод | доступність, затримка |
| Верифікація ІСТ | Стрес-тести й оцінка моделей | Методика експерименту | відтворюваність, надійність |

## 3.3. Наскрізний кейс A: оцінювання ШІ
**Проблема:** різні ШІ-моделі ефективні за різними вимірами та умовами. **Об'єкт:** функціонування інформаційно-аналітичної системи з інтелектуальними компонентами. **Можливий предмет:** модель агрегування критеріїв ефективності з контекстними пріоритетами. **Результат:** методика чи метод оцінювання. **Перевірка:** порівняння з лінійним агрегуванням, аналіз чутливості, вимірювання стійкості ранжування. Немає підстав визнавати «перевагу» нового методу без контрольних експериментів.

## 3.4. Наскрізний кейс B: управління ресурсами
**Проблема:** навантаження й доступні ресурси змінюються. **Об'єкт:** процес динамічного розподілу ресурсів ІСТ. **Предмет:** модель станів, дій, переходів, обмежень і винагороди, а також метод прийняття рішень. **Результат:** формалізована модель MDP або інша модель та метод управління. **Перевірка:** порівняння з фіксованими правилами й простими евристиками на синтетичних сценаріях, розподіл результатів за серіями запусків.

## 3.5. Наскрізний кейс C: адаптивний граф знань
**Проблема:** єдина послідовність навчальних матеріалів не враховує індивідуальний стан засвоєння. **Об'єкт:** функціонування адаптивної інформаційно-освітньої системи. **Предмет:** інформаційна технологія добору ситуацій та генерації матеріалів на основі графа знань. **Результат:** модель стану знань, метод добору та інтегрована технологія. **Перевірка:** тестові контрастні профілі, однаковий базовий граф, аналіз покриття й стабільності рекомендацій; педагогічні ефекти оцінювати окремими етично погодженими дослідженнями.

## 3.6. Наскрізний кейс D: інтеграція даних
**Проблема:** різнорідні джерела використовують несумісні структури даних і словники. **Об'єкт:** процес інтеграції даних у розподіленій ІСТ. **Предмет:** метод узгодження схем або семантичного відображення. **Результат:** метод з формальними правилами зіставлення. **Перевірка:** дані з контрольованими пропусками, неоднозначностями, еталонними зв'язками; метрики точності відповідностей, втрат та продуктивності.

## 3.7. Наскрізний кейс E: інтелектуальна СППР
**Проблема:** невизначеність та неоднорідність критеріїв порушує прозорість вибору. **Об'єкт:** процес підтримки прийняття рішень засобами ІСТ. **Предмет:** метод побудови й пояснення ранжування альтернатив. **Результат:** модель, метод, алгоритмічна реалізація. **Перевірка:** альтернативи з наперед визначеними властивостями, порівняння базових методів, аналіз чутливості до ваг та неповних даних.

## 3.8. Критерії добору напряму ад'юнктом
Кафедральна консультація повинна перевіряти доступ до безпечних даних, компетентність керівника, можливість формалізації, здійсненність експерименту, існування наукової прогалини та наявність найближчих аналогів. Пріоритет не повинен визначатися популярністю бібліотеки чи кількістю доступних демонстрацій.

## Практичне завдання
Побудуйте матрицю з п'яти кандидатних тем. Для кожної укажіть наукову прогалину (з джерелами), тип результату, дані, baseline, критерій успіху, загрози валідності та відповідність предметній області F6. Вибір теми обґрунтуйте доказами, а не інтуїтивною оцінкою.
