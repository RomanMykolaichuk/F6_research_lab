# Кейс D. Інтеграція різнорідних даних

Навчальний проєкт, не підтверджена наукова новизна.

## Постановка
Дані: Синтетичні каталоги документів з різними назвами полів.
Тип результату: Метод узгодження схем.
Кандидатна гіпотеза: Чи покращує комбінування ознак точність зіставлення на невідомих схемах?
Прогалина потребує перевірки: знайти найближчі аналоги, заповнити [матрицю](../sprint-7/analogue-matrix.md), встановити відмінність і контрприклад.

## Формалізація
Для полів x,y score=0.5 lexical+0.3 type+0.2 value; усі компоненти в [0,1]; поріг 0.75; неоднозначність при різниці двох найкращих <0.05 — ручний перегляд.

## Ручний приклад
Для (.8,1,.5) score=.8; для (.6,1,.5) score=.7. Перша пара проходить поріг, якщо немає близького конкурента.

## Протокол
Baseline: Точний збіг назв, лексичний метод, типізовані правила.
Метрики: Precision, recall, F1, частка abstain, час; розподіл за незалежними сімействами схем.
До запуску зафіксувати мінімальний ефект, незалежні одиниці, seed, розподіл train/validation/test (де є навчання), інтервали невизначеності. Зберегти сирі дані, код, версії, SHA. Не змінювати критерій успіху після тесту.

## Загрози валідності
Пороги добирати на validation; не використовувати еталонні зв’язки як ознаки. Перевірити пропуски та конфлікти типів.
